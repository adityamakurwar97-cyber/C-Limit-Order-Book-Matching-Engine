What is being measured?

16,000 events per run · 3 measured repetitions · seed 2026 · one warm-up per engine. The workload starts with 4,000 resting orders, followed by placements, cancellations and IOC sweeps.

Per-event latency includes core request processing. Throughput also includes per-event timing and result handling. JSON, network and browser rendering are excluded. The optimized engine maintains an ID index, depth totals and recent trade history; the reference has fewer bookkeeping features. This is a workload comparison, not an isolated data-structure experiment.

p99 is the latency at the 99th percentile of observed events. OS scheduling, thermal conditions and compiler settings affect results. No latency target or speedup is guaranteed.

A SMALL EXCHANGE, EXPLAINED.

Built to inspect.

The browser sends commands. Python transports them. C++ decides every execution.

01

Validate

Check positive IDs, prices and quantities. Reject reused IDs. Assign sequence internally so clients cannot choose queue priority.

protocol.hpp → Engine::submit()
02

Find the best price

Ordered maps keep the highest bid and lowest ask accessible. Each price level contains a FIFO linked list of orders.

std::map → Level → std::list
03

Match & account

Execute at the resting order's price. Subtract the minimum available quantity from both orders. Repeat across eligible levels.

min(incoming, resting)
04

Rest or cancel

GTC keeps the remainder. IOC and market instructions cancel it. FOK checks eligible liquidity first and executes only if the entire quantity is available.

filled + resting + cancelled = requested

Scope & engineering boundaries

One synthetic instrument. Positive integer ticks. Single-threaded engine, serialized local commands. In-memory state, with manual journal export and deterministic replay. No live trading, accounts, risk limits, self-trade prevention or durable crash recovery. UI shows up to 100 levels per side and 200 active orders; the engine stores more.

Market orders are unpriced, immediate orders in this simulator; no exchange-specific price collars. One tick is an abstract increment, not automatically ₹1. Benchmark results describe this machine and workload only.
